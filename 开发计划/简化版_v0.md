## 1. 唯一第一目标

做出一个 **10～20 分钟可重复** 的 Micro ARPG Loop：

1. 玩家改装备 / Support / 天赋后，技能体感明显变化。
2. 用变化后的 Build 挑战一张更危险、收益更高的地图。
3. 高密度战斗的性能路径可被测量，不要求第一轮就达标。

这一目标成立前：

- 不扩技能数量
- 不扩天赋树
- 不扩完整 Craft / Atlas / Unique 库
- 不上内容工厂

这一目标不成立时：继续加内容只会放大问题。

## 3. 三席编制

同时只允许 **I 和 R 各一个会话**。需要换模块时换上下文，不新开编制。

| 席 | 谁 | 职责 | 禁止 |
|---|---|---|---|
| **D 导演** | 人类 | 方向、砍机制、Slice 手感验收 | 不审类名、不写公式细节 |
| **I 实现** | AI 会话 1 | 当前阶段的唯一写代码席 | 不平行改第二个核心模块；不自造新架构名词 |
| **R 审阅** | AI 会话 2 | 编译、测试、重复实现、回退、文档是否同步 | 不开发新功能 |

I 覆盖原 A2–A8、A10 及切片所需的最少表现（原 A11–A13 的最低可用部分）。  
R 覆盖原 A1 + A9 的「门」+ A14 + A15。  
性能不是独立特工；R 在阶段门时跑测量，I 修瓶颈。

导演每个 Slice 只回答：

```text
1. 移动爽吗？
2. 技能爽吗？
3. 怪物杀起来爽吗？
4. Build 变化明显吗？
5. Loot 想捡吗？
6. Craft 有决策吗？
7. 更高风险地图值得去吗？
8. 画面是否清楚？
9. 美术是否统一到可接受？
10. 声音是否有冲击？
```

## 4. 并行规则（只留 4 条）

1. **同一时刻一个核心模块只有一个写者（I）。**
2. **接口只写在 `docs/RUNTIME.md`。** I 改接口必须同提交更新该文件；R 检查不一致即打回。
3. **禁止为赶任务复制第二套类似系统。** 优先复用 Tag / Modifier / Effect / Condition / Trigger。
4. **内容不得发明 Runtime 做不到的新机制。** 先扩机制，再写内容数据。

不再使用：Interface Change Request、跨 Agent 所有权矩阵、14 字段任务单作为日常格式。

## 6. 任务模板（5 字段）

```text
依赖：S0 工程可打开
```

### S1 能打

**目标：** 手感可被导演判断；密度可被测量。  
**不要求：** 真实系统 1440p / 120FPS / 300 怪一次过关。

合并原 Phase 1 性能尖刺与 Phase 4 手感原型，避免做两遍胶囊人。

I 做：

```text
点地移动 / 朝向 / 攻击距离 / 接近 / 出招 / 取消窗口 / 输入缓冲
3 个技能原型：近战、弹道、范围
最小动画：Idle / Run / Attack / Cast / Hit / Death
最小 VFX 与受击反馈（对象池）
最小打击音（可占位，但要有事件层）
Dummy 怪：可生成 100 / 200 / 300
简单转向 + AI LOD 开关
Profiler 一键场景（PerformanceArena）
```

不做：完整装备、完整天赋、Craft、Unique、完整 Combat Math。

R 做：

```text
记录：CPU / 主线程 / 渲染 / GPU / GC Alloc / Animator / 寻路 / 物理 / VFX / DrawCall / 内存
指出前 3 个瓶颈
确认无热路径明显 GC 爆炸
```

导演做：亲自打 10 分钟，回答第 3 节的 1–3、8–10。

**Gate S1**

- [ ] 导演认为移动和基础攻击「可以继续」
- [ ] 密度场景可复现测量
- [ ] 瓶颈清单存在（即使帧率未达标）
- [ ] 未引入「每个 Buff 一个 GameObject / 每个弹道一个 Rigidbody」这类禁止项

失败：修手感或修测量，不开始词缀和地图。

性能达标（1440p / 120FPS / 300 真实实体）**移出本门**，记为 **Gate S2P**，在 S2 循环可玩之后再打。

### S2 有循环

**目标：** Vertical Slice #1。这是第一目标的本体。

规模锁死（与 v1 Phase 5 对齐，不加码）：

```text
角色：1 个，Life / Mana，基础三属性
技能：3 Active + 6 Support（至少 1 个 Support 改变机制，不是纯 +伤）
装备：3～4 槽，Ordinary / Rare，至少 10 Affix，Socket / Link
天赋：10～20 节点，1～2 Notable，1 个机制节点
怪物：3 普通 + 1 Elite
地图：1 张，2～3 词缀，Stability，Reward Multiplier，Build Lock
制作：1 个随机 Craft + 1 个定向 Craft
表现：达到「能判断好不好玩」的最低质量，禁止全灰盒
```

循环：

```text
进图 → 杀怪 → 掉装备/资源 → 制作/换装/改 Link
→ Build 变化 → 选更危险词缀 → 再进图
```

Combat Math：只实现第 2.1 节子集，并写入 `COMBAT_MATH.md` + 黄金向量。

**Gate S2（玩法门，导演拍板）**

- [ ] 改 Support 或词缀或天赋后，技能差异肉眼可见
- [ ] 更高风险地图的收益可理解
- [ ] 死亡后可免费重构再挑战（图内仍锁 Build）
- [ ] 10～20 分钟内能完整走完两轮循环

**Gate S2P（性能门，S2 玩法通过后再打）**

- [ ] 在真实 Slice 系统（技能/词缀/命中/掉落/VFX/UI）下能量测 100 / 200 / 300
- [ ] 有瓶颈报告
- [ ] 若距 120FPS 过远：停止加内容，先改 Tick 频率 / Animator LOD / 转向 / 弹道 / 光影 / VFX / 对象池；仍不够才局部 Jobs/Burst
- [ ] **禁止第一反应 Full DOTS 重写**

S2P 失败：冻结内容扩张，只准优化。不阻断「导演已确认循环好玩」这一事实，但阻断 S3。
